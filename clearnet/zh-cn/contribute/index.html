投稿专栏

新闻导读的专栏欢迎投稿，写你对隐私、匿名网络、网络审查与开源生态的看法。这一页说明适合的题目、写法、署名与投稿的渠道。

其他语言：正體中文、English

专栏是新闻导读里由作者署名、写出自己看法的文章。导读整理各方的说法、不评判谁对，专栏则由作者提出主张。专栏的观点属于作者，不代表 anoni.net 社区的立场。欢迎研究者、项目维护者、在相关领域工作的人，以及关心这些议题的读者一起投稿。

适合的题目

主轴跟新闻导读相同，是隐私、匿名网络与网络审查，也包括这些工具依赖的开源生态。好几则新闻指向同一个变化，你对这个变化又有自己的看法时，就适合写成专栏。例如一项政策或平台规则改变之后，你在工作或使用上看到的影响，或你参与维护的项目遇到的取舍。

只转述一则新闻、没有自己主张的稿件，比较适合写成导读。主要用途是追查特定个人的工具，以及可能被滥用的操作步骤，专栏跟导读一样不收。

写法

整篇围绕一条主张，前两段就写出来。你的看法用第一人称写明，事实附上原文的链接，读者要分得出哪一句是事实、哪一句是你的判断。写到跟你看法不同的说法时，引用对方自己的文件，回应对方最有力的理由。

篇幅不设上限，每段写两到四句的完整段落，不用列表。粗体留给你最想传达的主张，网站会用专栏色的荧光笔底标出。写完可以只读粗体的句子，看看能不能读出你完整的主张。最后可以用一两个问题问读者。

正体中文、简体中文或英文都可以写，另外两个语系由维护者翻译，发布前会请你看过。用字照社区的写作风格规范，维护者审稿时会协助调整。详细的规则写在 GitHub 上的专栏写法。

界线

专栏是你的意见，下面几条界线跟导读一样适用：

  • 人名与组织只在理解新闻必要时保留，被点名、受攻击的当事人不写名字
  • 不描述特定地区、特定族群使用哪些工具，地区、族群与产品名称同时出现，就足以构成侦查线索
  • 不整篇翻译别人的文章，引用尽量短

署名

专栏一定要署名，本名或固定使用的笔名都可以，但不能用社区的名义。社区署名的专栏会读成社区的立场。

笔名会把同一个人写的文章串在一起，写得越多，从题目、时间与文风推回本人越容易。需要高度匿名的人要把这一点算进去。

投稿的渠道

不想在任何记录里留下身份的人，请维护者代发。稿件可以在社区的 Matrix 聊天室私信维护者、寄到 whisper@anoni.net（建议用 PGP 加密），或照上传敏感信息流程传递。维护者以自己的身份提交，记录里不会出现投稿者。

熟悉 GitHub 的人也可以自己在 anoni-net/news 开 PR。这样会留下 GitHub 账号、commit 的作者、email 与时区，具名投稿的人比较适合。

审稿与发布

维护者审稿时查事实、出处、用字与上面的界线，不改你的主张。事实与界线的修改请你接受，措辞与论点由你决定。审完排进发布时段，三个语系同时上线，文章跟其他导读一样以 CC BY 4.0 授权。
