新闻导读

关于新闻导读

anoni.net 新闻导读报道哪些主题、如何选题、核查、更正与跟进后续，三个语言版本的差异，以及报告错误的方式。

其他语言：正體中文、English

anoni.net 新闻导读由台湾的匿名网络社区 anoni.net 编写，整理国际上隐私、匿名网络与网络审查的新闻。我们比较熟悉科技与开源生态，所以从这个角度读新闻。每篇先用新闻写法交代发生了什么、谁受影响，再用「导读观点」说明背后的技术、读者现在能做的第一步，以及要付出的代价。

报道范围

导读分为以下几类，每篇归入其中一类，点击分类名称可以读到同一类的全部导读。

加密与通信
通信软件与云服务的加密设计，以及各国要求企业调取或扫描通信内容的政策与法案。
追踪与个人数据
网站与 App 的追踪代码、数据经纪商建立的个人档案，以及 App 与 AI 服务读取的个人数据。
监控与间谍软件
国家与企业的监控技术，包括间谍软件、人脸识别与车牌识别，以及相关的判决与调查。
审查与访问管制
各国与平台对上网、获取内容与发布 App 设下的限制或要求，包括网站封锁、年龄验证、实名制与开发者验证。
手机与 App
手机操作系统、App 商店与 App 的功能与政策变更，以及对隐私与安全的影响。
安全与诈骗
钓鱼、诈骗、入侵与数据泄露，以及普通用户可以采取的防范方式。
公民团体的科技实务
公民团体使用、评估或应对科技的方法，例如数字安全指南、记录与存证、社区网络。
每周短讯
每周整理几则没有单独成篇的隐私、匿名与审查新闻，每则一段。

与隐私、匿名网络和网络审查无关的科技新闻不写，例如一般的 AI 治理与科技行业的经营。只更新版本号、没有改变使用方式的发布公告，以及筹款、活动与人事公告也不写。

另有专栏导读历史，每个日期一页，回看隐私、匿名网络与网络审查在同一天发生过的事。

选题

候选新闻来自约三十个固定来源，包括数字权利组织、安全研究团队、开源项目与媒体，另外参考科技社区的每日精选。维护者先按标题挑选，再读原文确认能否写出导读观点。优先选读者今天就能下载、设置或照着做的题目，以及会改变现有做法的技术与政策变化。

核查

每一句事实都要能在原文或官方资料中找到出处，找不到出处的句子会删掉，或改写成推论的语气。工具与服务的现状，包括版本、价格、支持的平台与地区、有没有中文界面，在写稿当天回到官方页面确认，与原文不同时以官方资料为准。

每篇用到的原文与资料都列在文章的「原文」区块，附上出处与日期。导读观点为了比较各地情况而查的法规与统计，也列在同一个区块。

更正

文章发布后发现错误或信息过时，我们会同时修正三个语言版本。稿件放在公开的 GitHub 仓库，每一次修改的内容与时间都可以查到。

事件的后续

隐私与审查的新闻常延续好几个月。法案会修改、表决，功能会从测试版正式推出，有些事件过了一段时间才出现新的调查结果。导读过的事件如果有新进展，我们会另写一篇后续导读。后续的开头用一句话交代前情，没读过之前的文章也看得懂。之前那篇的标题下方会出现最新一篇的链接，文末也列出同一事件的每一篇导读，从任何一篇进来都能看到最新的进展。

三个语言版本

每篇同时发布正体中文、简体中文与英文三个版本，事实以正体中文版为准。导读观点则按读者的处境改写。简体中文版以中国境内与海外的读者为对象，写明在中国能否使用、如何获取。英文版的导读观点篇幅较长，加入亚洲各地法规与服务现状的比较，新闻的主角是美国或欧洲的产品时也一样。三个版本的导读观点因此不完全相同，各自引用的资料列在各自的原文区块。

署名

文章默认以「anoni.net 社区」署名，不写个人，不想留下个人痕迹的作者也能参与。内容是否正确，由可查证的出处与公开的修改记录来检验。

报告错误

发现事实错误、过时的信息或翻译问题，欢迎在 GitHub 提交 issue，写明是哪一篇、哪一句，能附上出处更好。不想使用 GitHub 账号的人可以发邮件到 whisper@anoni.net，建议用 PGP 加密。

阅读量与隐私

本站用自建的 Umami 统计阅读量，不使用 cookie，浏览器开启「请勿追踪」或 GPC 时不发送。除了页面浏览，也统计四种点击：原文区块的链接、订阅入口（记录渠道是 RSS、电子报或 Bluesky，位置在刊头、文章末尾或页脚）、首页的文章链接（记录来自焦点或时间轴）、文章页的朗读按钮（每次浏览只记第一次）。点击事件不包含链接的网址。阅读页面不需要 JavaScript，也不加载站外的字体与资源。onion 版本不加载统计，地址在每一页的页脚。
