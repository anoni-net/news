專欄是新聞導讀裡由作者署名、寫出自己看法的文章。導讀整理各方的說法、不評判誰對，專欄則由作者提出主張。專欄的觀點屬於作者，不代表 anoni.net 社群的立場。歡迎研究者、專案維護者、在相關領域工作的人，以及關心這些議題的讀者一起投稿。

## 適合的題目 {#topics}

主軸跟新聞導讀相同，是隱私、匿名網路與網路審查，也包括這些工具依賴的開源生態。好幾則新聞指向同一個變化，你對這個變化又有自己的看法時，就適合寫成專欄。例如一項政策或平台規則改變之後，你在工作或使用上看到的影響，或你參與維護的專案遇到的取捨。

只轉述一則新聞、沒有自己主張的稿件，比較適合寫成導讀。主要用途是追查特定個人的工具，以及可能被濫用的操作步驟，專欄跟導讀一樣不收。

## 寫法 {#writing}

整篇圍繞一條主張，前兩段就寫出來。你的看法用第一人稱寫明，事實附上原文的連結，讀者要分得出哪一句是事實、哪一句是你的判斷。寫到跟你看法不同的說法時，引用對方自己的文件，回應對方最有力的理由。

篇幅不設上限，每段寫兩到四句的完整段落，不用條列。**粗體留給你最想傳達的主張，網站會用專欄色的螢光筆底標出**。寫完可以只讀粗體的句子，看看能不能讀出你完整的主張。最後可以用一兩個問題問讀者。

正體中文、簡體中文或英文都可以寫，另外兩個語系由維護者翻譯，發布前會請你看過。用字照社群的[寫作風格規範](https://anoni.net/join/writing-style/)，維護者審稿時會協助調整。詳細的規則寫在 GitHub 上的[專欄寫法](https://github.com/anoni-net/news/blob/main/guides/column.md)。

## 界線 {#boundaries}

專欄是你的意見，下面幾條界線跟導讀一樣適用：

- 人名與組織只在理解新聞必要時保留，被點名、受攻擊的當事人不寫名字
- 不描述特定地區、特定族群使用哪些工具，地區、族群與產品名稱同時出現，就足以構成偵查線索
- 不整篇翻譯別人的文章，引用盡量短

## 署名 {#byline}

專欄一定要署名，本名或固定使用的筆名都可以，但不能用社群的名義。社群署名的專欄會讀成社群的立場。

筆名會把同一個人寫的文章串在一起，寫得越多，從題目、時間與文風推回本人越容易。需要高度匿名的人要把這一點算進去。

## 投稿的管道 {#submit}

不想在任何紀錄裡留下身分的人，請維護者代發。稿件可以在社群的 [Matrix 聊天室](https://matrix.to/#/#community:im.anoni.net)私訊維護者、寄到 `whisper@anoni.net`（建議用 PGP 加密），或照[上傳機敏資訊流程](https://anoni.net/join/upload-sensitive/)傳遞。維護者以自己的身分送出，紀錄裡不會出現投稿者。

熟悉 GitHub 的人也可以自己在 [anoni-net/news](https://github.com/anoni-net/news) 開 PR。這樣會留下 GitHub 帳號、commit 的作者、email 與時區，具名投稿的人比較適合。

## 審稿與發布 {#review}

維護者審稿時查事實、出處、用字與上面的界線，不改你的主張。事實與界線的修改請你接受，措辭與論點由你決定。審完排進發布時段，三個語系同時上線，文章跟其他導讀一樣以 CC BY 4.0 授權。
