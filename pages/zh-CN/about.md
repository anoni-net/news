anoni.net 新闻导读由台湾的匿名网络社区 anoni.net 编写，整理国际上隐私、匿名网络与网络审查的新闻。我们比较熟悉科技与开源生态，所以从这个角度读新闻，每篇先用新闻写法交代发生了什么、谁受影响，再用「导读观点」说明背后的技术、读者现在能做的第一步，以及要付出的代价。

## 选题 {#selection}

候选新闻来自约三十个固定来源，包括数字权利组织、安全研究团队、开源项目与媒体，另外参考科技社区的每日精选。维护者先按标题挑选，再读原文确认能不能写出导读观点。优先选读者今天就能下载、设置或照着做的题目，以及会改变现有做法的技术与政策变化。

## 核查 {#fact-checking}

每一句事实都要能在原文或官方资料中找到出处，找不到的推论会删掉，或写明是推论。工具与服务的现状，包括版本、价格、支持的平台与地区、有没有中文界面，在写稿当天回到官方页面确认，与原文不同时以官方资料为准。

每篇用到的原文与资料都列在文章的「原文」区块，附上出处与日期。导读观点为了比较各地情况而查的法规与统计，也列在同一个区块。

## 更正 {#corrections}

文章发布后发现错误或信息过时，三个语言版本会一起修正。稿件放在公开的 GitHub 仓库，每一次修改的内容与时间都查得到。

## 三个语言版本 {#languages}

每篇同时发布正体中文、简体中文与英文三个版本，事实以正体中文版为准。导读观点按读者的处境重写，简体中文版写给中国境内与海外的读者，交代在中国能不能用、如何获取。英文版篇幅较长，比较亚洲各地的法规与服务现状，新闻的主角是美国或欧洲的产品时也一样。所以三个版本的导读观点不完全相同，各自引用的资料列在各自的原文区块。

## 署名 {#byline}

文章默认以「anoni.net 社区」署名，不写个人。社区署名让不想留下个人痕迹的作者也能参与，写得好不好、对不对，由查得到的出处与公开的修改记录来检验。

## 报告错误 {#report}

发现事实错误、过时的信息或翻译问题，欢迎到 GitHub 的 [anoni-net/news](https://github.com/anoni-net/news/issues/new) 提交 issue，写明是哪一篇、哪一句，附上出处更好。不想使用 GitHub 账号的人可以发邮件到 `whisper@anoni.net`，建议用 PGP 加密。

## 阅读量与隐私 {#privacy}

本站用自建的 Umami 统计阅读量，不使用 cookie，浏览器开启「请勿追踪」或 GPC 时不发送。页面不需要 JavaScript，也不加载站外的字体与资源。onion 版本不加载统计，地址在每一页的页脚。
