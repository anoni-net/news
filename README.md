# anoni.net 新聞導讀

`anoni.net/news` 的文章與網站原始碼。介紹讓公民團體、記者與調查記者把工作做得更快、更安全的開源專案與科技工具，一則寫成一篇正體中文的導讀。每篇附原文連結、來源與日期、用自己的話寫的摘要，以及讀者如何取用：工具的授權、維護狀態、使用門檻與介面語言。[文件站](https://anoni.net/docs/)有合適的頁面時，附上延伸閱讀。

由[匿名網路社群 anoni.net](https://anoni.net/) 維護，是 anoni.net 底下的產品之一。

## 選題

優先選讀者今天就能下載、執行或照著做的內容，例如開源工具的新發布、公開方法與資料的調查手法、開放資料集與 API、記者與公民團體的數位安全工具。其次是會讓既有工作方式需要調整的變化，例如平台關閉 API、常用工具改變使用方式、新的監控手法與檢測方式。

版本公告、沒有公開方法的調查報導本身、純政策聲明與閉源產品的行銷文不選。主要用途是追查特定個人的工具也不選，導讀容易成為濫用的操作說明。

工具類的文章寫稿前先看過專案頁面，確認授權、最近一次發布的時間、使用門檻與介面語言。最近一年沒有發布的專案不選，除非文章本身就在說明它停止維護。導讀寫工具能做什麼、誰在維護、如何取得，不寫哪個地區、哪個族群的人在用它。

## 跟文件站的分工

| 內容 | 放在哪裡 |
|---|---|
| 新聞導讀（摘要與評註） | 本 repo |
| 外部文章的全文翻譯 | 文件站的 blog |
| 軟體更新日誌 | 文件站的 `changelog/` |
| 社群公告與活動 | 文件站的 blog |

導讀只寫摘要與評註，不整篇翻譯。原文的著作權屬於原作者，每一則都附上原文連結。

## 狀態

籌備中。網站由本 repo 的 `build.py` 產生，不採用現成的靜態網站產生器，理由、內容格式、網址規則與第一版不做的功能寫在 [`SPEC.md`](./SPEC.md)。開發指令與寫稿步驟在 [`AGENTS.md`](./AGENTS.md)。

## 寫作規則

照[貢獻者百科](https://anoni.net/docs/community/contributor-handbook/)的寫作風格規範，本 repo 不另外寫一份。給 AI 協作工具的說明在 [`AGENTS.md`](./AGENTS.md)。
