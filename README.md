# anoni.net 新聞導讀

`anoni.net/news` 的文章與網站原始碼。整理國際上隱私、匿名網路與網路審查的新聞，一則寫成一篇正體中文的導讀。我們從科技與開源生態的角度讀新聞，介紹背後有哪些專案與技術，可以成為保護隱私的解決方案，或讓需要它們的人把工作做得更有效率。每篇附原文連結、來源與日期、用自己的話寫的摘要，以及技術觀點，篇幅控制在幾分鐘讀得完。

由[匿名網路社群 anoni.net](https://anoni.net/) 維護，是 anoni.net 底下的產品之一。

## 選題

主軸是隱私、匿名網路與網路審查。在這個範圍裡，優先選能帶出具體專案或技術的新聞，例如開源工具的新發布或重大功能、附上方法與程式碼的研究、開放資料集與 API、數位安全的工具與流程。其次是會讓既有做法需要調整的變化，例如常用工具改變使用方式、加密與匿名工具面臨的政策變動、新的監控手法與檢測方式。

跟隱私、匿名與審查無關的科技新聞、版本公告、沒有技術面可談的政策聲明與閉源產品的行銷文不選。主要用途是追查特定個人的工具也不選，導讀容易成為濫用的操作說明。

工具類的文章寫稿前先看過專案頁面，確認授權、最近一次發布的時間、使用門檻與介面語言。最近一年沒有發布的專案不選，除非文章本身就在說明它停止維護。導讀寫工具能做什麼、誰在維護、如何取得，不寫哪個地區、哪個族群的人在用它。

## 跟文件站的分工

| 內容 | 放在哪裡 |
|---|---|
| 新聞導讀（摘要與評註） | 本 repo |
| 外部文章的全文翻譯 | 文件站的 blog |
| 軟體更新日誌 | 文件站的 `changelog/` |
| 社群公告與活動 | 文件站的 blog |

導讀只寫摘要與評註，不整篇翻譯。原文的著作權屬於原作者，每一則都附上原文連結。

## 狀態

籌備中。網站由本 repo 的 `build.py` 產生，不採用現成的靜態網站產生器，理由、內容格式、網址規則與第一版不做的功能寫在 [`SPEC.md`](./SPEC.md)。開發指令與寫稿步驟在 [`AGENTS.md`](./AGENTS.md)。

## 寫作規則

照[貢獻者百科](https://anoni.net/docs/community/contributor-handbook/)的寫作風格規範，本 repo 不另外寫一份。給 AI 協作工具的說明在 [`AGENTS.md`](./AGENTS.md)。
