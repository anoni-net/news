# 專欄的寫法

格式見 `SPEC.md`「專欄」。導讀整理各方的考量、不評判誰對，專欄由作者署名，寫出作者自己的判斷。查證的標準跟導讀相同，作者的看法可以有立場，事實不能因此寫得比原文更肯定。2026-11 第一期是 `posts/2026-11-25-open-source-contributions-ai.md`，寫之前先讀一遍。

## 選題

主軸跟導讀相同，是隱私、匿名網路與網路審查，也包括這些工具依賴的開源生態。好幾則新聞指向同一個變化、一則導讀寫不完，作者又有清楚的主張時，適合寫成專欄。單一事件寫得完的仍然寫導讀，只想整理各方說法、沒有自己主張的，也寫導讀。

寫稿前先在 `posts/` 搜尋同主題的導讀。已經寫過的事件在專欄裡用一兩句帶過，連到那一篇，最後放進延伸閱讀。

## 主張

- 整篇一條主張，前兩段就寫出來，之後每一節都連回它，不寫成依時間排列的事件整理
- 作者的看法用第一人稱寫明，例如「我認為」、「我的看法是」。讀者要分得出哪一句是事實、哪一句是作者的判斷
- 先處理跟主張觀點不同的例子，不挑容易反駁的。寫成另一個面向的觀察，例如「從入口的角度看 xz 後門，會得到不同的看法」，不寫成「對我的主張最不利」或「我承認」這類比輸贏、讓步的說法。反方的說法引用它自己的文件，不從作者的批評反推
- 可以批評做法與制度，不揣測具名的個人或組織的動機
- 推論寫明是推論，數字只用來源寫的口徑，例如廠商的計數不寫成官方的數字

## 結構與篇幅

- 第一段寫正在發生的變化與作者要談的問題，不先堆日期、版本號與數字
- 依論點分節，每節一個 `##` 小標題，用名詞片語，寫明錨點
- 不設字數上限，比導讀長是正常的。每段兩到四句，一段只處理一件事，全部寫成完整的段落，不用條列
- 最後一節之前寫作者的結論與讀者能做的事，例如使用者能看哪些訊號、想參與的人能從哪裡開始。結尾不總結全文
- 延伸閱讀之前可以用一段問題收尾，問讀者能從自己的經驗回答的具體問題，一兩題就好，例如第一期問讀者常用的隱私工具有沒有寫 AI 與權限的規則
- 粗體只留給作者要傳達的主張，頁面會用專欄色的螢光筆底標出，讀者略讀時只看粗體也能讀到作者的看法。術語、數字與一般的強調不加粗。一篇幾處就好，太多會分不出重點。段首的整句不能加粗（寫作風格規範的 `bold-lead-sentence`），主張在段首時只加粗句子裡的關鍵詞組
- 選完粗體之後，從頭到尾只讀粗體的句子，檢查能不能讀出作者完整的主張。缺了哪一環，例如前言的核心主張、從個案推到結論的那一步、從批評轉到建議的那一句，就補上。跟其他粗體沒有因果關係的支線觀察，就算是作者的看法也不加粗，略讀時會讓人以為那是全文的重點。2026-11 第一期這樣檢查之後，從五處調整成七處
- 最後一節是 `## 延伸閱讀 {#further-reading}`，列 2 到 4 篇本站的導讀，寫 clearnet 的完整網址，每篇一行、寫出一句跟本文的關係。這一節是例外，可以用條列

## 事實與界線

事實的寫法照 `guides/posts.md`「事實與不確定」、「用字」與「資料拼接句」：每一句事實都要對得到原文，出處寫進句子，原文的限制一定寫進去，會變的狀態寫出查證日期。

`AGENTS.md` 的三條界線照用，包括不整篇翻譯原文、人名與組織只在理解新聞必要時保留，以及不描述特定地區、特定族群使用哪些工具。被點名、受攻擊的當事人不寫名字。專欄是作者的意見，界線一樣適用，作者具名也不例外。

## 三個語系

zh-CN 與 en 照 zh-TW 翻譯，不加區域段落。專欄的論點屬於作者，譯者不另外延伸。en 一樣照英文版的寫作風格規範調整句子，自稱的部分改成作者的第一人稱。翻譯時的檢查照 `guides/ai-workflow.md`「寫稿與翻譯的子代理」，區域段落那兩條不適用。

投稿者看的是網站上的投稿頁（`pages/contribute.md`），這份的規則改了，投稿頁也要一起看。邀稿的作者用三個語系的任一個寫，另外兩個版本由維護者負責。能聯絡上作者時，請作者看過譯稿再發布。

## 審稿

審稿檢查事實、出處、寫作規則與界線，不改作者的主張。各方的句數不必對等，但每一句的歸屬要清楚，作者的看法不能寫成事實，某一方的說法也不能寫成作者的看法。

輪數照 `guides/ai-workflow.md`「審稿的輪數」。審稿修完之後派一位模擬讀者，只給成稿，請他回答下面五題，各自引用原句。用 Claude Code 時，`news-reader` 的問題是給導讀的，派它讀專欄時在指示裡附上這五題：

1. 作者的主張是什麼
2. 哪些句子分不出是事實還是作者的看法
3. 作者提到的反方說法，讀起來有沒有被扭曲或只挑了容易反駁的部分
4. 哪些地方讀不懂
5. 如果只能改一件事，會改什麼

邀稿的稿件由維護者審。事實與界線的修改請作者接受，措辭與論點由作者決定。
